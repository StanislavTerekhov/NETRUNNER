# NETRUNNER 1.0 — проверка безопасности

Дата: 2026-10-30. Ручной аудит кода main/preload/renderer и конфигурации сборки, плюс автоматические проверки.

## Модель угроз

1. **Текст модели и содержимое репозитория недоверенные.** Модель может ошибаться или быть «уговорена» содержимым файлов
   (prompt injection); репозиторий может содержать вредоносный конфиг.
2. **Агент выполняет команды** в системе пользователя.
3. **Утечка кода/переписки** в облако (запрещено спецификацией).
4. **Другие локальные процессы** могут пытаться управлять NETRUNNER/OpenCode.

| Инференс | `llama-server` запускается самим NETRUNNER на 127.0.0.1 со случайным API-ключом; облачных провайдеров в коде нет; движок агентов принимает только loopback-бэкенд; загрузки моделей и рантайма — только в ONLINE TOOLS и с записью в журнал | `llamacpp.ts`, `runtime-install.ts`, `opencode.ts`, `forge/common.py` |

| Git | Чекпоинты через временный индекс — HEAD, ветки и индекс пользователя не меняются; идентификаторы чекпоинтов проверяются по списку | `git.ts` |
| Параллельные агенты (1.2) | Задания пишут только в свой worktree (вне проекта, `external_directory: deny` относительно него); в проект — только через MERGE с подтверждением в окне main-процесса и чекпоинтом перед слиянием; DISCARD тоже подтверждается; id заданий проверяются по шаблону; junction `node_modules` отсоединяется до удаления worktree | `tasks.ts`, `git.ts`, `ipc.ts` |
| Файлы из проводника (1.3) | Создание/переименование только внутри проекта (лексическая и realpath-проверка), имена проверяются; удаление — в корзину Windows после подтверждения в окне main-процесса | `workspace.ts`, `ipc.ts` |
| Языковые серверы (1.3) | pyright — встроенный, в Electron utility process, связь через message port (без сокета на loopback); серверы из PATH — stdio. | Веб-инструменты (1.6) | Только в ONLINE TOOLS; режим подтверждений (СПРАШИВАТЬ / ОГРАНИЧЕННО / ПОЛНОСТЬЮ) применяется в main-процессе, окна подтверждения — системные. Запросы к loopback, частным и link-local адресам запрещены, в том числе после DNS и на каждом редиректе (страница не может увести запрос на локальный llama-server). Отмена — только пока файл не менялся после записи; созданный файл уходит в корзину | `chat-files.ts`, `workspace.ts`, `ipc.ts` |

| Сборка | Electron Fuses: `RunAsNode` off, `NODE_OPTIONS` off, `--inspect` off, проверка целостности asar on, загрузка только из asar on, шифрование cookie on | `electron-builder.json` |

## Найдено и исправлено в Фазе 6

| # | Проблема | Риск | Исправление |
|---|---|---|---|
| 1 | В сборке был включён `RunAsNode`: `NETRUNNER.exe` с `ELECTRON_RUN_AS_NODE=1` работал как обычный Node.js (готовый инструмент для запуска произвольного кода под видом доверенного exe) | средний | Electron Fuses; проверено `@electron/fuses read` |
| 2 | node-pty закрывал терминал через `fork` (Electron-as-Node) — несовместимо с п.1 | функционально | Терминал завершается деревом через `taskkill /T` — заодно гаснут запущенные в нём команды |
| 3 | `fs:write` без лимита размера (у чтения был 5 МБ) | низкий (DoS диска) | Лимит 5 МБ |
| 4 | `conversations:save` без лимита | низкий | Лимит 20 МБ JSON, нормализация полей |
| 5 | `network:csp-violation` можно было вызывать в цикле, раздувая журнал | низкий | Не более 20 записей/с |
| 6 | OpenCode при `--port=0` слушал фиксированный 4096 — конфликт с собственным OpenCode пользователя; предсказуемый порт | низкий | Свободный порт от ОС |

## Остаточные риски (осознанно приняты)

1. **Подтверждение — последняя линия защиты.** Если пользователь одобрит вредную команду, агент её выполнит.
   Карточка показывает точную команду/диф; ARCHITECT и REVIEWER не могут редактировать файлы. С 1.7 ALWAYS разрешает
   только ровно эту команду или этот файл (не шаблон OpenCode вроде `npm *`), до остановки движка; список виден и отзывается.
2. **Прокси ≠ песочница.** Команды агента (`node`, `npm`, `git`) — отдельные программы; программа, игнорирующая
   `HTTP(S)_PROXY`, может выйти в сеть в обход прокси. С 1.7 раздел FIREWALL закрывает интернет программам NETRUNNER
   (OpenCode, llama-server, ripgrep) и любым программам, которые оператор добавит сам; общие `node`/`git`/`python`
   NETRUNNER сам не блокирует — они нужны пользователю и вне NETRUNNER. Правила применяет оператор (UAC).
3. **Агент действует с правами пользователя** в пределах папки проекта (`external_directory: deny`), но `bash`
   технически может обратиться к любому файлу пользователя — поэтому каждая команда ждёт подтверждения.
4. **Smoke-режим** с 1.7 вырезан из релизного установщика при сборке (`vite build --mode release`); он есть только в
   тестовой сборке `npm run dist:test` и в режиме разработки.
5. **Серверы моделей** (с 1.1 — llama.cpp вместо Ollama) слушают только 127.0.0.1 и требуют случайный API-ключ, новый
   при каждом запуске; другие локальные процессы не могут ими пользоваться. Рантайм скачивается из официальных релизов
   ggml-org на GitHub; с 1.7 каждый архив сверяется с SHA-256, который публикует GitHub (без суммы — не ставится),
   обновления проверяются кнопкой. Сами бинарники llama.cpp не подписаны (подпись — дело ggml-org).
6. **Установщик не подписан** (нет сертификата подписи кода).
7. **ripgrep не поставляется в установщике** — ставится кнопкой SETUP (официальный релиз) или берётся из PATH; без него `grep`/`glob` агента не работают офлайн.
8. **Языковые серверы анализируют код проекта** (pyright читает файлы и запускает `python` для поиска пакетов) — это чтение в пределах машины, сети они не используют.
9. **HumanEval запускает код модели на этой машине.** Отдельный процесс, временная папка, урезанное окружение и тайм-аут — это не песочница: код работает с правами пользователя и теоретически может читать его файлы или выйти в сеть. Задачи HumanEval безобидны, а модель — своя локальная; шаг BENCH можно не выбирать.

10. **Установка и запуск чужих репозиториев** (`repo_install`, `repo_run`) выполняет их скрипты с правами пользователя — это не песочница. В режимах СПРАШИВАТЬ и ОГРАНИЧЕННО каждое такое действие подтверждается с точной командой; в ПОЛНОСТЬЮ — нет. Текст из интернета может содержать указания для модели (prompt injection): в ограниченном режиме опасные действия всё равно ждут подтверждения.

## Автоматические проверки

- `npm audit --omit=dev`: **0 уязвимостей** в поставляемых зависимостях. Остаются moderate в `minimatch` внутри electron-builder
  (только сборка).
- `dompurify` (транзитивно через Monaco) зафиксирован на исправленной 3.4.17+ через `overrides`.
- Unit-тесты на безопасность: выход за пределы папки (`..`, абсолютные, UNC, диски, NUL, junction), политика эндпоинтов, облачные
  модели, прокси (HTTP и CONNECT блокируются без обращения к хосту), окружение агента без ключей, разбор Markdown без HTML,
  экранирование команды брандмауэра, лимиты записи.
