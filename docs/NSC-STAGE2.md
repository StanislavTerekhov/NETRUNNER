# NSC, этап 2 — монитор обратной интерференции (RI)

Дата: 2026-11-04. Данные — `%USERPROFILE%\NETRUNNER\nsc\stage2\`.

«Обратная интерференция» — это когда что-то другое на компьютере замедляет модели NETRUNNER, или когда NETRUNNER занимает больше ресурсов, чем разрешает правило «минимум 50 % свободно». Монитор следит за этим, пока загружена модель, и показывает, что происходит и насколько это вредно по замерам.

## 1. Сначала замер: что реально мешает Coder-Next

`test/nsc/stage2-interference.live.test.ts`: Coder-Next запущен так же, как его запускает NETRUNNER для агентов (контекст 64K, 2 слота, 8 потоков). Рядом создаётся помеха, и прогоняются те же задачи, что в базовой линии этапа 0.

| Помеха | Генерация, ток/с | Длинный промпт, ток/с | CPU системы | Свободно RAM |
|---|---|---|---|---|
| Без помех (3 прогона) | 20.9 / 22.3 / 21.3 | 394* / 617 / 585 | 28–30 % | 7–10 GB |
| 8 занятых потоков (чужие 37 % CPU) | 21.3 | 585 | 58 % | 8.7 GB |
| 16 занятых потоков (чужие 59 % CPU) | 20.8 | 608 | 81 % | 8.7 GB |
| **24 занятых потока (чужие 81 % CPU)** | **12.7 (−39 %)** | 548 | 99 % | 8.3 GB |
| Чужой процесс держит RAM, свободно 8 GB | 21.8 | 622 | 28 % | 7.9 GB |
| Чужой процесс держит RAM, свободно 3 GB | 22.3 | 589 | 27 % | 3.0 GB |
| **Вторая модель на GPU после загрузки (VRAM 12.0 из 12.3 GB)** | 22.0 | **515 (−15 %)** | 29 % | 1.2 GB |

\* Первый прогон после загрузки модели: часть весов ещё не в кэше.

Что из этого следует:
- **CPU.** Пока чужие программы занимают до ~60 % процессора, Coder-Next не замедляется: ему хватает свободных ядер под свои 8 потоков. При 81 % генерация падает на 39 %.
- **RAM.** Нехватка RAM вплоть до 1.2 GB свободной Coder-Next **не замедлила**. Вывод этапа 0 («агенты читали промпт медленно из-за нехватки RAM») не подтвердился и исправлен в docs/NSC-STAGE0.md.
- **VRAM.** Вторая модель, загруженная на видеокарту после Coder-Next, заняла её до предела. Чтение промпта замедлилось на 15 %, генерация — нет.

## 2. Монитор

`electron/main/services/ri-monitor.ts`, данные в интерфейс — по каналу `ri:state`.

- Работает только пока загружена модель. Каждые 5 с снимает CPU, RAM и GPU (дёшево), раз в 15 с — собственные процессы NETRUNNER (на Windows это дороже). Без модели не делает ничего.
- `LlamaRuntime.footprint()` сообщает, сколько VRAM взяли серверы моделей, сколько VRAM было занято другими в момент загрузки и лежат ли веса частично в RAM.

Правила (`assessInterference`, пороги `RI_LIMITS` взяты из замеров выше):

| Находка | Когда | Основание |
|---|---|---|
| CPU занят другими | чужие ≥ 70 % (предупреждение), ≥ 80 % (критично), и веса модели лежат в RAM | при 59 % потерь нет, при 81 % −39 % |
| VRAM занята другими | после загрузки модели другие заняли ещё ≥ 1 GB, и видеокарта заполнена ≥ 95 % | −15 % на чтении промпта |
| Почти нет свободной RAM | < 1 GB, и веса модели лежат в RAM | до 1.2 GB потерь нет; ниже не мерили — предупреждение осторожное |
| Медленнее обычного | ответ или задача агента медленнее 70 % от медианы прошлых прогонов этой модели (нужно ≥ 5 прошлых) | сравнение с реальной историей скорости из SQLite |

**Решение от 2026-11-04:** скорость важнее правила «50 % свободно». Находки «сверх бюджета» убраны. Доли NETRUNNER по каждому ресурсу по-прежнему видны в таблице монитора, но тревогой не считаются.

Ограничения:
- Загрузку GPU по процессам Windows не отдаёт, поэтому доля NETRUNNER в GPU не показывается («—»).
- Предупреждение о CPU появляется и тогда, когда модель простаивает: это прогноз «если сейчас дать задачу, она пойдёт медленнее», а не измеренная потеря.
- Модели, целиком лежащие в VRAM (например, 4B), правила про CPU и RAM не затрагивают. Это проверено вживую: 4B на CPU-помеху не отреагировала.

## 3. Интерфейс

- **Строка состояния:** «ПОМЕХИ: N», «СВЕРХ БЮДЖЕТА» или «ПОМЕХ НЕТ». Индикатор виден только пока загружена модель, по клику открывается МОНИТОР СИСТЕМЫ.
- **МОНИТОР СИСТЕМЫ → ПОМЕХИ:**
  - доля NETRUNNER и общая загрузка по CPU, RAM, VRAM и GPU;
  - текущие находки с измеренным значением, порогом и тем, что показал замер;
  - история закончившихся находок.
- Тексты на русском и английском.

## 4. Проверки

- Юнит-тесты (`test/ri-monitor.test.ts`, 7 тестов): каждое правило, свой и чужой CPU, отсутствие утверждений без данных (нет nvidia-smi, своя нагрузка ещё не измерена), сравнение с медианой, ведение истории. Всего: 193 пройдено.
- Живая проверка в приложении (`NETRUNNER_SMOKE_RI=<модель>` в smoke): загружается Coder-Next, затем 25 с все логические CPU заняты чужими потоками.
  - До нагрузки: только «сверх бюджета» (VRAM 83 %).
  - Во время: «CPU занят другими: 100 %», в строке состояния «ПОМЕХИ: 1».
  - После: находка ушла в историю.
  - Smoke 46/46, скриншот — `test/output/smoke-ri.png`.
- С 4B та же проверка честно не сработала: модель целиком на GPU, и правило её не касается.
