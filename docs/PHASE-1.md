## Безопасность (реализовано уже сейчас)

- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`; preload собирается в CJS (требование sandbox).
- В renderer доступен только `window.netrunner` с allowlist каналов (`electron/shared/ipc.ts`); `ipcRenderer` не экспонируется.
- Main проверяет отправителя каждого IPC-вызова (наше окно, главный фрейм, наш URL).
- Доступ к ФС только внутри открытого воркспейса: лексическая проверка (`..`, абсолютные пути, другие диски, UNC, NUL) **и** проверка `realpath` (симлинки/junction наружу блокируются).
- `workspace:open` по пути принимает только папки, ранее выбранные пользователем через диалог.
- Запись атомарная (tmp + rename) и отказывает, если файл изменён на диске после открытия.
- CSP: в продакшене `script-src 'self'`, `connect-src 'self'`; навигация, `window.open`, `<webview>` и все permission-запросы запрещены; renderer не может обращаться ни к одному хосту, кроме собственного бандла (лог `[netguard]`).
- Аудит: критическая уязвимость `dompurify` (транзитивно через Monaco 0.57, попадает в renderer) закрыта через `overrides` → 3.4.17. Остаются 15 moderate в `minimatch` внутри electron-builder — только инструменты сборки, в приложение не попадают.

## Найденные и исправленные дефекты

1. Junction внутри воркспейса не показывался в дереве → симлинки теперь отображаются по типу цели, доступ по-прежнему проверяется через realpath.
2. `settings.json` с UTF-8 BOM (типично для PowerShell 5.1) молча сбрасывал настройки → BOM удаляется, добавлен тест.

## Блокеры и риски для следующих фаз

1. **Ollama не установлен** на машине. Для Фазы 2 нужен установленный Ollama (https://ollama.com/download) и хотя бы одна модель. Оборудование: RTX 3060 12 ГБ + 64 ГБ RAM → комфортно модели ~7–14B в Q4/Q5 полностью в VRAM; 20–32B — с частичной выгрузкой на CPU.
2. **Проект лежит в OneDrive.** `node_modules` и `release` синхронизируются (сотни МБ). Рекомендуется перенести проект, например в `C:\dev\netrunner`, или исключить эти папки из синхронизации.
3. **Нативные модули** (node-pty для терминала, better-sqlite3 для памяти) потребуют сборки под Electron 42. Если prebuild-бинарников нет — понадобятся Visual Studio Build Tools (C++).
4. **npm 11 `allow-scripts`** блокирует install-скрипты: бинарник Electron пришлось скачать вручную (`node node_modules/electron/install.js`). На новой машине — то же.
5. Установщик не подписан → SmartScreen покажет предупреждение.
6. Smoke-режим включается переменной окружения `NETRUNNER_SMOKE_OUT` и в упакованном приложении; до релиза (Фаза 6) ограничить его неупакованными сборками.
