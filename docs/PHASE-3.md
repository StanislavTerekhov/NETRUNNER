## Изоляция и безопасность агента

- **Сетевой прокси NETRUNNER** (`net-proxy.ts`): OpenCode и терминал получают `HTTP(S)_PROXY` на локальный прокси, который
  применяет сетевой режим к каждому соединению без DNS-запросов и пишет журнал (`network:log`, UI — Фаза 5).
  В STRICT OFFLINE проходит только loopback.
- **Конфиг проекта не может ослабить политику**: `OPENCODE_DISABLE_PROJECT_CONFIG=1` (иначе чужой `opencode.json` в репозитории
  мог бы выдать `permission: allow`).
- Отключены: автообновление, загрузка каталога моделей (models.dev), загрузка LSP, внешние плагины и скиллы, импорт настроек
  Claude Code, встроенный web UI (флаги извлечены из бинарника OpenCode 1.19.5).
- Из окружения агента вырезаются `*_API_KEY`, `*_TOKEN`, `OPENAI*`, `ANTHROPIC*`, `AWS_*` и т. п. — OpenCode не сможет
  автоматически подключить облачного провайдера по найденному ключу.
- Сервер OpenCode защищён случайным паролем (basic auth) — другие локальные процессы не могут им управлять.
- Собственные XDG-каталоги в `userData/opencode` — глобальная конфигурация пользователя не читается и не меняется.
- Остановка движка убивает всё дерево процессов (`taskkill /T`), включая запущенные агентом тесты.

## Модель для агента

`qwen3.6:35b-agent` — производная от `qwen3.6:35b` с `num_ctx 32768` (создаётся через `/api/create`). Причина: системные
промпты OpenCode большие, а через OpenAI-совместимый `/v1` Ollama не принимает размер контекста в запросе.

## Найденные и исправленные дефекты

1. **Агент зависал на первом подтверждении.** OpenCode 1.19.5 шлёт `permission.asked` (формат v2) и ждёт ответ на
   `POST /permission/{id}/reply`, а типы v1 SDK описывают устаревшие `permission.updated` и `/session/{id}/permissions/{id}`.
   Обрабатываются оба формата; ответ — через актуальный эндпоинт.
2. Необработанный `ECONNRESET` в прокси, когда клиент рвёт заблокированное соединение, — добавлены обработчики ошибок сокетов.
3. Ввод в xterm в smoke-тесте: `insertText` не доходит до xterm — тест печатает посимвольно.
4. Скриншоты smoke-теста отставали на кадр (Windows не перерисовывает перекрытое окно) — в smoke-режиме отключён
   `backgroundThrottling`, снимок после двух кадров `requestAnimationFrame`.
5. `opencode-ai` был в `dependencies` → инсталлятор тянул бы 3 копии бинарника (~600 МБ). Перенесён в devDependencies,
   в сборку попадает один `opencode.exe` через `extraResources`.

## Блокеры и ограничения

1. **ripgrep (требует вашего решения).** Инструменты OpenCode `grep`/`glob` используют ripgrep и при первом запуске скачивают его
   с GitHub — в офлайне это заблокировано, и они падают («glob ripgrep execution failed»). Агент справляется через `read`/`bash`,
   но поиск по большому проекту будет хуже. Решение: один раз скачать официальный ripgrep 15.1.0
   (`github.com/BurntSushi/ripgrep/releases`, ~2 МБ, MIT/Unlicense) в `build/vendor/ripgrep` и поставлять в инсталляторе.
   Моя попытка скачать его автоматически была отклонена системой разрешений — нужно ваше подтверждение.
2. **Прокси ≠ брандмауэр.** Программа, игнорирующая `HTTP(S)_PROXY` и открывающая сырые сокеты, прокси не заметит.
   Правила Windows Firewall для `opencode.exe` (по явному согласию, нужны права администратора) — Фаза 5.
3. **Скорость.** `qwen3.6:35b-agent` на 12 ГБ VRAM: задача из примера — ~1 мин; на большом проекте шагов больше.
   `netrunner-qwen3:8b`/`qwen3:8b` быстрее, но качество агентной работы у 8B заметно ниже (не измерялось в этой фазе).
4. Сам репозиторий NETRUNNER не под git — чекпоинты в нём недоступны, пока не нажать GIT INIT.
5. Параллельные агенты, очередь задач и история в SQLite — Фаза 4.
