# Фаза 8 — LM Studio, параллельные агенты, раскладки рабочего места

Дата: 2026-10-31. Версия 1.2.0. Закрывает три пункта из списка недоработок: LM Studio как источник моделей (§2.11),
параллельные агенты, именованные раскладки с пристыкованным терминалом.

## LM Studio как источник моделей

NETRUNNER находит папку моделей LM Studio и показывает её GGUF-файлы в MODEL VAULT рядом со своими (значок
**LM STUDIO**, id вида `lmstudio:<издатель>/<репозиторий>/<файл>.gguf`). Файлы читаются на месте и запускаются
**своим** llama.cpp: копирования нет, сам LM Studio не запускается, его сервер (порт 1234) не используется — два движка
не делят 12 ГБ VRAM, а политика сети и ключи остаются под контролем NETRUNNER.

- Поиск папки: выбранная вручную (MODEL SOURCES → CHOOSE FOLDER, только через системный диалог) → `downloadsFolder` из
  `~/.lmstudio/settings.json` → `~/.lmstudio/models` (с учётом `~/.lmstudio-home-pointer`) → старая `~/.cache/lm-studio/models`.
- Модели LM Studio можно назначать на роли GENERAL / AGENT / MEMORY. **Удалять их NETRUNNER отказывается** (их ведёт LM Studio).
- Если LM Studio и NETRUNNER смотрят в одну папку, модели не дублируются.

На этой машине LM Studio не установлен: панель честно показывает «not found». Проверено тестами на временной папке с
настоящими GGUF-заголовками (поиск папки, каталог, запрет удаления).

## Параллельные агенты

AGENT CONTROL → **PARALLEL 1–4** (применяется при старте движка).

- **1** — как раньше: задачи строго по очереди, прямо в проекте, чекпоинт перед каждой.
- **2–4** — одновременно идут до N *заданий* (одна задача или весь конвейер; шаги конвейера внутри задания — по порядку).
  Каждое задание, которое может менять файлы, работает в **своём git worktree** — отдельной копии проекта, снятой с
  чекпоинта (вместе с незакоммиченными правками). В проект ничего не попадает, пока оператор не нажмёт **MERGE**.
  Одиночные ARCHITECT/REVIEWER (только чтение) идут прямо в проекте.
- Модель одна: `llama-server` запускается с `-np N` и контекстом 65K **на каждый** слот (`-c 65536×N`), так что задания
  делят веса, а не дублируют их (Coder-Next + 27B в 64 ГБ вместе всё равно не помещаются).
- OpenCode: один сервер, сессии в разных каталогах (`?directory=`), события всех каталогов через `/global/event`
  (проверено на 1.19.5). `external_directory: deny` действует относительно worktree.
- **WORKTREE JOBS**: список изменённых файлов задания, **MERGE** (подтверждение в окне main-процесса → чекпоинт проекта →
  трёхстороннее слияние) и **DISCARD**. Файл, который оператор не трогал, просто заменяется; изменённый с обеих сторон
  сливается `git merge-file`, при конфликте остаются маркеры и кнопка REVIEW MERGE (откат через GIT). Задание без
  изменений убирает свой worktree само.
- Ignored `node_modules` подключается в worktree как junction, чтобы тесты шли без переустановки; перед удалением
  worktree junction отсоединяется — копия проекта не затрагивается (проверено тестом).
- Подтверждения: каждая карточка APPROVALS показывает, от какой задачи и из какого worktree запрос.

## Раскладки рабочего места

Меню **LAYOUT** в заголовке окна и палитра команд (`Layout: …`).

| Пресет | Что на экране редактора |
|---|---|
| CLASSIC | проводник + редактор; терминал — отдельный раздел (как раньше) |
| CODE | проводник + редактор, терминал под редактором |
| AI PAIR | проводник + редактор + чат NEURAL CORE справа, терминал под редактором |
| SIDE TERMINAL | редактор + терминал справа |
| FOCUS | только редактор |

В меню переключаются проводник, чат рядом с кодом и место терминала (свой раздел / под редактором / справа); изменённую
раскладку можно сохранить под именем (до 20, хранятся в `settings.json`). Размеры панелей запоминаются для каждой
раскладки отдельно. **Терминал не перезапускается при перестыковке**: оболочка живёт в main-процессе, панель при
повторном монтировании подхватывает её и показывает последние 200 000 символов вывода.
