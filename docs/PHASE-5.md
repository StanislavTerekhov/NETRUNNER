# Фаза 5 — ADVANCED HUD: отчёт

Дата: 2026-10-30. Статус: **завершена**. Версия 0.5.0.

## Что сделано

| Требование | Реализация |
|---|---|
| System monitor | Экран SYSTEM MONITOR: CPU (загрузка, история, 32 потока по ядрам), память (система и сам NETRUNNER), GPU (загрузка, температура, мощность, частота, VRAM), AI RUNTIME (модели, загруженные в Ollama, с реальным разделением VRAM/RAM; процессы `ollama`/`llama-server`/`opencode` — CPU и RAM), диски, сетевой трафик машины |
| Только реальные данные | CPU считается по разнице `os.cpus()`, GPU — `nvidia-smi`, процессы/диски/сеть — `systeminformation`. Температура CPU в Windows без драйвера производителя недоступна — показывается «n/a» с объяснением, а не число. Выборка идёт, только пока экран открыт |
| Network monitor | Экран NETWORK MONITOR: режим сети, четыре уровня защиты с реальным статусом, журнал сетевой активности (фильтры ALLOW/BLOCK, по источнику), сводка по хостам. Журнал хранится в SQLite (`network_log`, до 5000 записей) |
| Полнота журнала | Пишутся: запросы через прокси агента и терминала, запросы интерфейса, отменённые фильтром Electron, нарушения CSP (о них страница сообщает сама — CSP блокирует запрос раньше сетевого слоя Electron), загрузки моделей (их выполняет сервер Ollama) |
| Принуждение на уровне ОС | Опциональное правило Windows Firewall: исходящий Block для `opencode.exe`, удалённый адрес `Internet` (loopback и локальная сеть остаются доступны — локальный Ollama работает). Включается кнопкой, через нативное подтверждение и окно UAC |
| Визуализация агентов | Граф конвейера в AGENT CONTROL: четыре узла-роли со статусом и временем, анимированное ребро к выполняющемуся шагу (отключается при `prefers-reduced-motion`), счётчики вызовов инструментов |
| Метрики производительности моделей | Каждый ответ NEURAL CORE записывается в `inference_metrics` (ток/с генерации, ток/с промпта, загрузка). Виджет INFERENCE PERFORMANCE: средняя и лучшая скорость по моделям + график последних ответов. Виджет AGENT TASKS: среднее время и успешность по ролям |
| Настраиваемые панели | CUSTOMIZE: каждый виджет можно скрыть или переставить; раскладка сохраняется между запусками. Ширины панелей редактора сохранялись с Фазы 1 |
| Отрисовка Markdown | Ответы агентов и Neural Core: заголовки, таблицы, списки, цитаты, код, `inline`, **жирный**. Только React-элементы, без `innerHTML` — текст модели не может внедрить разметку |

## Найденные и исправленные дефекты

1. Запрос интерфейса к внешнему сайту блокировался, но не попадал в журнал: CSP отсекает его до сетевого слоя Electron,
   где стоял логгер. Добавлен обработчик `securitypolicyviolation`; main-процесс проверяет URL и пишет запись.
2. `systeminformation.currentLoad()` на Windows занимает ~0,5 с и запускает процессы — загрузка CPU считается по `os.cpus()`;
   тяжёлые измерения (процессы, сеть, диски) — раз в 6 с и 30 с.

## Ограничения

- Температура CPU недоступна (нужен драйвер датчиков с правами администратора, например LibreHardwareMonitor).
- Сетевой трафик в виджете — по всей машине, не только NETRUNNER (Windows не даёт трафик по процессам без ETW и прав администратора).
- Правило брандмауэра покрывает только `opencode.exe`; команды, которые запускает агент (`node`, `npm`, `git`), — отдельные
  программы. Они получают переменные прокси, но их сырые сокеты брандмауэр не блокирует (общесистемное правило для `node.exe`
  сломало бы другие программы пользователя).
- Метрики скорости пишутся для NEURAL CORE; для агентов OpenCode не отдаёт тайминги генерации — измеряется время задач.
